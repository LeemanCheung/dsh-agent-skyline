# DSH 插件生态与爆款选题分析

> 调研快照：2026-08-26。目标不是预测“必然爆火”，而是在现有生态中选择传播概率、完成质量和长期留存最优的方向。


## 调研口径与限制

本报告基于三类公开信号交叉验证：你账号下公开 DSH 仓库清单、`awesome-dsh-plugin` 的插件与 Star 快照、GitHub `topic:dsh-plugin` 及名称/描述关键词检索。它覆盖了当前公开可发现的主流样本与直接竞品，但不把 GitHub 搜索结果宣称为“绝对无遗漏的全站数据库导出”；私有仓库、未打 Topic、刚创建或未被索引的项目可能不在样本中。候选方向评分属于产品判断，不是对未来 Star 的保证。

`awesome-dsh-plugin/data/stars.json` 在 2026-08-14 的快照中，头部项目呈现明显断层：`dsh-TUI` 684、`dsh-vision-toolkit` 283、`oh-dsh` 143、`dsh-tianshu-tui` 110、`forkprobe` 64、`dsh_workflow` 52、`mstar-harness` 41、`dsh-turn-rewind` 33。大量单点小工具则集中在 0–9 Star。这个分布支持“完整体验层、强能力扩展、可见结果”比单一按钮或轻量面板更容易传播，但 Star 仍受发布时间、作者影响力和渠道分发影响。

## 1. 你的现有 DSH 插件版图

当前公开仓库已经形成明显的个人产品风格：重视可视化、审美、趣味化和复杂 Agent 行为的直观呈现。

| 方向 | 代表仓库 | 已覆盖价值 |
| --- | --- | --- |
| 工作流可视化 | `dsh-task-dag` | Agent Teams、Workflow、通信与依赖拓扑 |
| Token / 成本分析 | `dsh-token-usage` | 使用量、成本、趋势和 AI 分析 |
| 桌宠与养成 | `dsh-whale-companion`、`dsh-whale-animation` | 鲸鱼成长、动画与陪伴感 |
| Agent 玩法 | `dsh-agent-arena` | Agent 对战和竞技展示 |
| 个性化外观 | `dsh-skin-studio`、`dsh-qq2007-skin`、`dsh-vibe-pack` | 主题、复古皮肤和视觉氛围 |
| 生成能力 | `dsh-image-gen` | 图像生成入口 |
| 使用引导 | `dsh-agent-preset-recommender` | Agent / Preset 推荐 |
| 生态整理 | `awesome-deepseek-harness`、`awesome-dsh-plugin` | 插件收录、分类与发现 |

### 已形成的优势

- 对“不可见的 Agent 行为”进行视觉化的能力强；
- 能将硬核开发功能包装为低理解门槛的产品；
- 已有统一的 DSH Web 插件接入、构建、CI 和双语文档经验；
- 鲸鱼、QQ 皮肤、DAG 等项目证明你适合做“截图就能理解”的插件。

### 当前缺口

- 缺少一个 **分享优先** 的产品：用户使用后会自然生产可传播内容；
- 缺少跨 Session 持续积累的个人身份资产；
- 部分项目功能价值强，但截图需要解释，传播链路偏长；
- 现有插件之间尚未形成一个能充当个人品牌入口的“旗舰视觉产品”。

## 2. GitHub DSH 插件生态信号

从当前 Awesome 清单和 GitHub Topic 检索看，Star 明显集中在两类项目：

1. **替代交互界面或完整体验层**：例如 TUI、独立客户端、全局交互增强；
2. **显著扩展模型能力边界**：例如视觉、Computer Use、Runtime、Workflow。

相反，单点统计、按钮增强、简单格式转换和轻量面板普遍停留在较低传播水平。原因并不是这些工具无用，而是：

- 同质项目多，名字和截图难以区分；
- 用户使用结果不可见，不会成为社交内容；
- 卖点需要长篇解释，缺少三秒识别度；
- 功能价值停留在“省一步”，没有身份感、收藏感或持续成长。

### 已拥挤方向

实际检索发现以下选题已有多个直接竞争项目：

- Agent Office / Desktop / Cowork；
- Session Replay / Record Replay；
- Wrapped / Recap；
- Achievements；
- Meme；
- 桌宠、皮肤、状态 HUD；
- 单纯对话分享和单张统计卡。

其中 `dsh-wrapped` 已实现 `/wrapped` 命令生成 Session SVG 卡片，因此再做普通“年度总结卡”难以建立品类认知。

## 3. 候选方向评分

评分范围 1–10。传播性考察三秒理解、截图表现和用户自传播；留存考察是否反复使用；差异化考察已有直接竞品；可交付性考察能否在一个完整版本中达到高质量。

| 候选 | 传播性 | 留存 | 差异化 | 可交付性 | 综合判断 |
| --- | ---: | ---: | ---: | ---: | --- |
| Agent Skyline：会话生成城市 | 9.5 | 8.8 | 9.2 | 9.0 | **首选** |
| Wrapped Pro：周报 / 年报卡 | 8.4 | 6.8 | 5.2 | 9.2 | 已有直接竞品，易被视为增强版 |
| Agent Office：像素办公室 | 8.8 | 7.5 | 4.8 | 6.5 | 方向拥挤，资产成本高 |

| Skill Radar / Plugin Finder | 5.8 | 8.4 | 6.2 | 8.0 | 有用但传播性不够强 |

## 4. 最终选择：Agent Skyline

### 一句话产品定义

**每一次 Agent 工作都会建造一座只属于你的程序员城市。**

### 为什么这个方向成立

#### 4.1 视觉隐喻天然成立

代码、工具调用、测试、Agent 协作本身就有“建设复杂系统”的语义。把它映射为城市，不需要教育用户：建筑越多、城市越复杂，代表本次任务越丰富。

#### 4.2 每个用户都会得到不同结果

城市由类别分布、复杂度、工具数量、错误恢复和 Agent 协作共同决定，并使用稳定种子生成。分享内容具备个体差异，能够触发比较和讨论。

#### 4.3 同时满足即时反馈和长期留存

- 当前 Session：完成任务后立即查看；
- Today / 7-day：形成日常复盘；
- All-time：形成持续成长的个人资产；
- Landmarks：提供长期解锁目标。

#### 4.4 隐私边界可清晰证明

传播类插件最危险的是泄露 Prompt、文件名或业务内容。Agent Skyline 从数据层直接丢弃原文，只保留类别、状态、时长和时间戳。隐私不是一个开关，而是数据模型本身的约束。

#### 4.5 可以形成自传播闭环

```text
完成 Agent 任务
→ 生成独特城市
→ 导出高审美卡片 / 动图
→ 发布到社区
→ 其他用户看到安装线索
→ 安装并生成自己的城市
→ 继续分享和比较
```

## 5. v1.0 产品决策

### 必须做

- 当前会话、今天、近 7 天、全部历史；
- 稳定、确定性的程序化城市；
- 建城回放和时间轴；
- 四套完整主题，不做零散换色；
- PNG、SVG、分享文案；
- City ID、Archetype、District、Landmarks；
- 默认匿名项目标签；
- 本地去重历史和一键清除；
- 中英文、移动端、Reduced Motion；
- 隐私泄漏自动测试。

### 明确不做

- v1 不做云端排行榜，避免账号、成本和隐私负担；
- 不调用 LLM 给用户“性格判断”，避免额外 Token 与伪科学感；
- 不读取 Prompt 生成标题；
- 不依赖 Git 仓库，保证非代码任务也能使用；
- 不做复杂 3D 引擎，避免性能、兼容性和包体失控；
- 不做付费功能或远程服务，先最大化安装转化。

## 6. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 用户误以为上传了会话内容 | UI 常驻本地隐私徽标，导出卡明确写明 no prompts / no paths / no cloud |
| 不同 DSH Node 结构导致分类缺失 | 防御式字段提取、未知类别降级为 Other、核心逻辑与 Host 解耦 |
| 城市长期看起来重复 | 稳定种子 + 类别配色 + 高度、冠顶、天线、灯光、地标多维变化 |
| 大会话建筑过多影响性能 | 将实际事件压缩为最多 48–72 栋视觉建筑，指标仍保留完整总量 |
| 本地历史重复计数 | 使用哈希后的 Session Key 做幂等 Upsert |
| 导出 PNG 浏览器兼容性 | Canvas 失败自动回退 SVG |
| 插件沦为一次性玩具 | Today / 7-day / All-time、地标与后续 Profile Badge 提供持续使用理由 |

## 7. 成功指标

首月不应只看 Star，而应按完整漏斗衡量：

| 层级 | 指标 | 建议目标 |
| --- | --- | ---: |
| 发现 | README 首图到安装说明滚动率 | > 55% |
| 转化 | 仓库访问到安装尝试 | > 12% |
| 激活 | 安装后成功打开城市 | > 70% |
| 价值 | 激活用户完成一次导出 | > 30% |
| 留存 | 7 日内再次打开 Today / 7-day | > 25% |
| 传播 | 导出用户中发布或复制文案 | > 20% |
| 反馈 | Issue / Discussion 中功能性反馈占比 | > 60% |

不接遥测时，可通过 GitHub Traffic、Star 增长、Issue 内容、社区帖子互动和用户主动上传的城市图进行近似判断。

## 8. 后续护城河

Agent Skyline 的护城河不是“画了城市”，而是逐步形成一套兼容多插件的 **Agent Activity Visual Language**：

- `dsh-task-dag` 提供协作拓扑，成为城区道路与卫星区；
- `dsh-token-usage` 提供本地用量，成为能源与灯光密度；
- `dsh-whale-companion` 可作为城市上空的稀有访客；
- 城市种子可离线交换，而不交换任何会话数据；
- GitHub Profile / README Badge 让城市离开 DSH 后仍持续曝光。

这使它有机会成为你已有插件矩阵的视觉入口，而不是一个孤立项目。
